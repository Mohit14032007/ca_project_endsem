## 1. Executive Summary & Anomaly Description

During the Phase 2.5 audit, an inconsistency was identified in the Phase 2 Smoke Test documentation (`SMOKE_TEST_RESULTS.md`). 

Specifically, for Run **S3 (CSTP LRU)**:
- Table Section 2 ("Demands & Hits") reported **114 Coalesced Fresh Misses**.
- Table Section 4 ("Memory Traffic") reported:
  - **Demand Bytes Transferred:** `9,865,003,008 bytes` ($112 \times 88,080,384\text{ bytes}$)
  - **Speculative Bytes Transferred:** `1,673,527,296 bytes` ($19 \times 88,080,384\text{ bytes}$)
  - **Total DDR5 Bytes Transferred:** `11,538,530,304 bytes` ($131 \times 88,080,384\text{ bytes}$)

This discrepancy prompted two critical audit questions:
1. Did the simulation engine actually execute **112** or **114** physical demand transfers?
2. If 114 fresh demand misses occurred, why was demand traffic reported as 112 expert transfers?

## 3. Root Cause Determination

The audit definitively establishes:
1. **The LLMSimulator execution engine is 100% physically correct.** It correctly recorded 114 demand transfers and 17 prefetch transfers.
2. **The JSON telemetry exporter is 100% correct.** It exported $10,041,163,776$ demand bytes and $1,497,366,528$ speculative bytes.
3. **The discrepancy was purely a human markdown transcription error:**
   - In Run S1 (Baseline LRU), there are 112 fresh demand misses and exactly 112 demand transfers ($9,865,003,008\text{ bytes}$).
   - When constructing the markdown summary table in `SMOKE_TEST_RESULTS.md`, the author accidentally copied the S1 baseline value (`9,865,003,008`) into the S3 column for `Demand Bytes Transferred`.
   - Then, the author computed speculative bytes by subtracting that incorrect baseline number from the correct total ($11,538,530,304 - 9,865,003,008 = 1,673,527,296$), creating the appearance of 19 speculative transfers.

## 5. Standardized Units Harmonization (GB vs GiB)

To prevent future confusion between decimal and binary memory capacity conventions, all reporting in Point 4 adheres to the following definitions:
- **Decimal Gigabytes ($\text{GB}$):** $1\text{ GB} = 10^9\text{ bytes} = 1,000,000,000\text{ bytes}$.
- **Binary Gibibytes ($\text{GiB}$):** $1\text{ GiB} = 2^{30}\text{ bytes} = 1,073,741,824\text{ bytes}$.

### Distinguishing Host Runtime from Simulated Latency
Previous tables also contained ambiguous headers like "Total Execution Time". In all Point 4 reporting:
- **Simulated GPU Execution Time / Latency (ms):** The cycle-accurate simulated GPU hardware execution duration (e.g., $167.30\text{ ms}$ for S1).
- **Host Wall-Clock Runtime (s):** The elapsed wall-clock execution time of the C++ simulation process running on the host CPU (e.g., $2.30\text{ s}$ for S1). Host runtime must never be conflated with simulated GPU latency.
