## 1. Executive Summary

This forensic audit investigates how LLMSimulator selects, ingests, generates, and executes expert routing decisions for **MoE Suite**, **MoE Anywhere**, and **DeepSeek-style synthetic routing**. We independently verified whether the simulator's generated routing execution records (`expert_routing.csv`) match the original recorded Top-8 expert decisions from the underlying Parquet datasets at the token, sequence, layer, and rank levels.

### Primary Audit Verdicts:
1. **Replay Fidelity for Replayed Steps (100.00% Exact Ordered Match):**  
   For all replayed tokens across MoE Suite ($L=75, K=8$) and MoE Anywhere ($L=40, K=8$), the simulator executes **the exact 8 experts in the exact original Top-K rank order** recorded in the Parquet source datasets.
   - **MoE Suite:** **$100.00\%$** exact ordered match across all audited tokens in A1, A2, A3, A4, C1, C2, and C3. Zero set mismatches, zero rank reordering, and zero invalid expert IDs.
   - **MoE Anywhere:** **$100.00\%$** exact ordered match across all audited tokens in A5, A6, B1, B2, B3, and B4. Zero set mismatches, zero rank reordering, and zero invalid expert IDs.
2. **Multi-Sequence Batch Isolation Verified (Zero Cross-Contamination):**  
   In multi-tenant batched experiments (B1, B2, B3, B4), independent prompt streams (Prompts 60, 61, 62, 63) are allocated to independent `SequenceInfo` instances. Every sequence executes **100.00% match** with its designated prompt and **0.16%–0.53%** with non-designated prompts (pure background random coincidence). The known synthetic routing collision bug does **not** contaminate real trace replay.
3. **Critical Defect Discovered — Final-Token Early Popping & Synthetic Fallback:**  
   In `src/scheduler/sequence.cpp:14`, sequence termination is governed by `total_len = input_len + output_len - 1`. Because the auto-regressive generation loop runs for `iter` steps ($iter = output\_len$), sequences finish **exactly one token early** (after $T - 1$ steps). When the completed sequence is popped at step $T - 2$, `Scheduler::fillSequenceQueue` automatically injects a dummy sequence via `pushDummySeq` to maintain the batch size. Consequently, for the **single final token (Step $T-1$)**, the simulator silently falls back to synthetic uniform random routing rather than the real trace.
4. **Synthetic Routing Artifacts Quantified:**  
   In synthetic mode (A7, A8), expert IDs are generated by `Scheduler::getRandomExpert` using a shared PRNG (`mt19937`, seed 777) and stored in a `std::set<int>`. Because `std::set` sorts elements in ascending numerical order, `topk_rank` (1..8) in synthetic mode represents sorted numerical order, not router confidence scores. Furthermore, `cached_routing` keys by `(token_id, cur_layer)` without sequence ID, causing identical multi-sequence collisions if synthetic routing is run with $B > 1$.

## 4. Real vs. Synthetic Selection Mechanism

The routing mode selection is governed strictly by the presence and non-emptiness of `simulation.trace_file` in the YAML configuration:

```cpp
// File: eval/test_deepseekv3_mixtral_style.cpp, Lines 125-128 & 321
std::string trace_file = trace_file_cli;
if (trace_file.empty() && config["simulation"]["trace_file"]) {
  trace_file = config["simulation"]["trace_file"].as<std::string>();
}

if (!trace_file.empty()) {
  // BRANCH 1: Real Trace Replay Mode
  scheduler->loadRealTrace(trace_file, max_batch_size, num_moe_layers, model_config.num_routed_expert, model_config.top_k, iter);
  for (int b = 0; b < max_batch_size; b++) {
    Sequence::Ptr new_seq = Sequence::Create(b, input_len, output_len);
    new_seq->get_expert_from_list = true;
    scheduler->sequence_queue.push_back(new_seq);
  }
} else {
  // BRANCH 2: Synthetic Random Generation Mode
  for (int b = 0; b < max_batch_size; b++) {
    scheduler->pushDummySeq(input_len, output_len);
  }
}
```

### Audit Findings on Mode Selection:
1. **Zero Silent Fallback in `loadRealTrace`:** In `src/scheduler/scheduler.cpp:610-685`, if the trace file does not exist, cannot be opened, has incomplete tokens, or contains out-of-bounds expert IDs, the loader throws a fatal C++ exception (`std::runtime_error`) and terminates execution. It **never** silently falls back to random routing during trace loading.
2. **Deterministic Sequence Tagging:** Each sequence created in Branch 1 has `get_expert_from_list = true` and `expert_seq_id = b`. This unconditionally routes the sequence through the real trace lookup table.
3. **Synthetic Activation:** When `trace_file` is omitted from YAML (as in A7 and A8), Branch 2 executes, creating sequences with `get_expert_from_list = false`.

## 7. Synthetic Routing Implementation & Artifacts

### 7.1 Generator Implementation
In `src/scheduler/scheduler.cpp:141-153`:
```cpp
std::set<int> Scheduler::getRandomExpert(int top_k) {
  static unsigned int seed = 777;
  static std::mt19937 generator(seed);
  static std::uniform_int_distribution<int> distribution(0, model_config.num_routed_expert - 1);

  std::set<int> route;

  while (route.size() < top_k) {
    int seq_id = (distribution(generator) % model_config.num_routed_expert);
    route.insert(seq_id);
  }
  return route;
}
```

### 7.2 Forensic Characteristics:
1. **Sampling Without Replacement:** Enforced by `route.insert()`. Duplicates are discarded until `route.size() == 8`.
2. **Ascending Order Artifact (`DISCREPANCY`):** `std::set<int>` in C++ is implemented as a Red-Black Tree, which automatically orders elements in ascending numerical order. When elements are pushed to `expert_vec` in `sequence.cpp:240`, `topk_rank` reflects sorted numerical value, not neural routing confidence.
3. **`cached_routing` Collision Vulnerability (`DISCREPANCY`):** In `sequence.cpp:227`, the cache key is `std::make_pair(token_id, cur_layer)`. Because `seq_id` is omitted, if synthetic routing is executed with $B > 1$, all sequences in the batch retrieve the identical cached expert set. In our baseline campaign, synthetic routing was strictly restricted to $B=1$ (A7, A8), preventing this bug from causing collisions.

## 10. Bugs, Discrepancies, and Root-Cause Analysis

### Defect 1: Final-Token Off-by-One Early Termination & Dummy Sequence Fallback
- **Location:** `src/scheduler/sequence.cpp:14` and `src/scheduler/scheduler.cpp:320`.
- **Root Cause:**
  ```cpp
  // src/scheduler/sequence.cpp:14
  total_len = input_len + output_len - 1;
  ```
  In auto-regressive decoding, a sequence generating `output_len` tokens starts at `current_len = input_len` and increments by 1 per step. At step `output_len - 2`, `current_len` reaches `input_len + output_len - 1`.
  In `src/scheduler/scheduler.cpp:320`:
  ```cpp
  if (seq->current_len == seq->total_len) {
    batch->pop(seq);
  }
  ```
  The sequence is popped **one token before the requested `iter` steps complete** (e.g., at token 127 instead of token 128).
  Then in `eval/test_deepseekv3_mixtral_style.cpp:429`:
  ```cpp
  scheduler->fillSequenceQueue(step_device_time, cumulative_device_time);
  ```
  Because a queue slot is now empty, `fillSequenceQueue()` invokes `pushSeq(1)`. Because `scheduler->real_data` was `false`, `pushSeq()` calls `pushDummySeq()`.
  This injects a brand-new dummy sequence (Request 2) with `get_expert_from_list = false`, which executes uniform random routing for the final step.
- **Impact:** Across all experiments, exactly $T-1$ tokens are authentic real trace replay, and exactly 1 token is a synthetic fallback. This accounts for:
  - 600 fallback records in A1, C1–C3 (75 layers $\times$ 8 experts).
  - 320 fallback records in A5, A6 (40 layers $\times$ 8 experts).
  - 640 fallback records in B1, B3 (2 seqs $\times$ 40 layers $\times$ 8 experts).
  - 1,280 fallback records in B2, B4 (4 seqs $\times$ 40 layers $\times$ 8 experts).
- **Recommended Correction:**
  Change `sequence.cpp:14` to:
  ```cpp
  total_len = input_len + output_len;
  ```
  And in `eval/test_deepseekv3_mixtral_style.cpp:321`, explicitly set `scheduler->real_data = true;`.

---

### Defect 2: Synthetic `cached_routing` Key Lacks Sequence ID
- **Location:** `src/scheduler/sequence.cpp:227`.
- **Code:**
  ```cpp
  auto route_key = std::make_pair(token_id, cur_layer);
  auto it = cached_routing.find(route_key);
  ```
- **Impact:** Only affects synthetic routing with $B > 1$. Sequences $1 \dots B-1$ copy Sequence 0's random routing. Real trace replay is **immune** because `get_expert_from_list = true` completely bypasses `cached_routing`.
- **Recommended Correction:** Include sequence ID: `std::make_tuple(seq_id, token_id, cur_layer)`.

### Defect 3: Ascending Sorted Numerical Order in Synthetic Mode
- **Location:** `src/scheduler/scheduler.cpp:141-153`.

- **Impact:** Experts in synthetic mode are sorted numerically in ascending order. `topk_rank` does not represent router gate scores. Real trace replay is **immune** because it loads genuine unsorted Top-K rankings from the Parquet traces.
