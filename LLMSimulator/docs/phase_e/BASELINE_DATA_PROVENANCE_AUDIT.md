## 1. Executive Summary

This forensic provenance audit establishes the end-to-end data lifecycle for all 15 configurations in the baseline campaign. We trace the exact transformations from raw dataset files on disk, through conversion and ingestion routines, configuration parameters, scheduling mechanics, to physical DRAM/HBM access dispatches and output trace generation.

### Primary Provenance Conclusions:
1. **Deterministic, Unbroken Chain of Custody for Real Traces:**  
   Both real datasets (**MoE Suite** and **MoE Anywhere**) follow a fully deterministic, verifiable ingestion pipeline:
   - **MoE Suite:** Raw Parquet (`corpus-12-typescript-migration-planner.parquet`) $\rightarrow$ Extractor (`export_trace_for_simulator.py::export_moe_suite`) $\rightarrow$ Intermediate CSV (`ms_task12_t*.csv`) $\rightarrow$ YAML (`simulation.trace_file`) $\rightarrow$ Ingestion (`Scheduler::loadRealTrace`) $\rightarrow$ Direct Array Dispatch (`BatchedSequence::update_expert`).
   - **MoE Anywhere:** Raw Parquet (`e1-sage-a1.5.parquet`) $\rightarrow$ Extractor (`export_trace_for_simulator.py::export_moe_anywhere`) $\rightarrow$ Intermediate CSV (`ma_*.csv`) $\rightarrow$ YAML (`simulation.trace_file`) $\rightarrow$ Ingestion (`Scheduler::loadRealTrace`) $\rightarrow$ Multi-Sequence Array Dispatch (`BatchedSequence::update_expert`).
2. **In-Memory Generation for Synthetic Routing:**  
   Configurations A7 and A8 omit `simulation.trace_file`. Synthetic routing decisions are **never** read from or written to intermediate CSV files prior to simulation; they are generated dynamically in C++ memory via `Scheduler::getRandomExpert` (`std::mt19937`, fixed seed 777, `std::set<int>` ascending order).
3. **Trace-to-Output Fidelity ($100.00\%$ Exact Ordered Match on Replayed Tokens):**  
   Record-level comparison against raw Parquet tables confirms that all replayed tokens ($0 \le t < T - 1$) achieve a **$100.00\%$ exact ordered match** with original source routing. There is zero expert reordering, zero set corruption, and zero layer misalignment.
4. **Final-Token Defect Documented (T−1 Authentic / 1 Fallback):**  
   Because `Sequence::Sequence()` initializes `total_len = input_len + output_len - 1` (`sequence.cpp:14`), sequences terminate one token early. At step $T-1$, `Scheduler::fillSequenceQueue` injects a dummy sequence via `pushDummySeq()`, which executes uniform random routing for the single final step.

## 2. Directory Structure and Output Artifact Inventory

The baseline execution environment follows a standardized, modular directory layout in `results/endsem_phase_e/final_baseline/`:

```
results/endsem_phase_e/final_baseline/
├── configs/               # 15 YAML configuration files (A1.yaml - C3.yaml)
├── traces/                # 12 intermediate CSV traces extracted from raw Parquet
└── runs/                  # 15 dedicated run output directories (A1 - C3)
    ├── <config_id>/
    │   ├── csv/           # Per-token hardware summary metrics (*_ramul_decode.csv)
    │   ├── raw/           # Gantt chart traces (empty; export_gantt: false)
    │   ├── traces/        # Detailed microarchitectural trace logs
    │   │   ├── expert_cache.csv    # LRU cache actions (HIT, MISS, EVICT, INSERT)
    │   │   ├── expert_load.csv     # DRAM/HBM transfer duration & latency
    │   │   └── expert_routing.csv  # Every routed expert decision (req, tok, layer, rank, exp)
    │   └── stdout_stderr.log       # Full console stdout and stderr log
```

### Purpose of Output Subdirectories:
- **`csv/`:** Contains the primary performance table `deepseekV3_synthesis_<Lin>_<Lout>_..._ramul_decode.csv`. It records per-step latency (ns), cumulative time, queueing delay, component compute times (`fc_comp`, `attn_comp`, `moe_comp`), DRAM memory stalls (`moe_dram`), and energy metrics.
- **`raw/`:** Configured via `gantt_directory`. Because `export_gantt: false` was set to prevent massive host disk consumption, this directory remains clean.
- **`traces/`:** Contains high-resolution event logs generated by the simulation core:
  - `expert_routing.csv`: Logged by `BatchedSequence::update_expert()`. Records the exact expert selected for every `(request_id, token_id, layer_id, topk_rank)`.
  - `expert_cache.csv`: Logged by `Device::is_expert_resident()` and `Device::mark_expert_resident()`. Records cache residency checks, insertions, hits, and LRU evictions.
  - `expert_load.csv`: Logged by `LinearModule::run()`. Records every tensor transfer ($W_1, W_3, W_2$), start/end cycles, latency, and memory source (`OFFCHIP_DRAM` vs `HBM`).

The comprehensive file-by-file inventory is recorded in [`BASELINE_DIRECTORY_INVENTORY.csv`](file:///home/mohman/ca_project/LLMSimulator/docs/phase_e/BASELINE_DIRECTORY_INVENTORY.csv).
